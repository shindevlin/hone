Calibration Formula

At each era N boundary, the chain reads the current wall-clock and computes:

remaining_ms = btc_end_ms − now_ms
remaining_eras = RECYCLE_ERA − N   // = 5 − N
series_sum = 2remaining_eras − 1
base_epoch_ms = remaining_ms ÷ (4,200,000 × series_sum)

// Stores per-era durations (base, 2×base, 4×base, …) in chain_param:era_epoch_ms:N

The series_sum term encodes the geometric structure: if the base epoch is b, the remaining supply is exhausted in 4.2M×b + 4.2M×2b + … + 4.2M×2r-1b = 4.2M×b×(2r−1) milliseconds.

Oracle Layer — Automatic BTC Tracking

No governance. No voting. Automatic.

HONE nodes that also run a Bitcoin full node submit BtcHeightReport entries to the chain. These are used to refine the target end timestamp automatically, with no human intervention required.

  • Signed by an active clock-node posting key (trusted role)
  • Height must be monotonically increasing — rewinding rejected
  • Implied block rate must be within ±10% of 10 minutes (540–660 s)
  • Reports older than 720 epochs are ignored (~6 hours at era 0)
  • Chain holds 7-entry rolling median → stored as chain_param:btc_end_ms
  • Era calibration reads chain_param:btc_end_ms in preference to the compile-time constant

Precision grows each decade: by era 4 (starting 2081) Bitcoin's block schedule is known to within weeks, so HONE's final epoch durations converge to within ±1 epoch (~7 minutes) of the BTC last-coin event.
