# HONE MCP For Claude Design

Date: 2026-07-05

## Thesis

HONE should expose an MCP server so Claude can orchestrate HONE workflows directly. This is especially important for video generation, because the value is not just model execution. The value is planning, job decomposition, routing, revision handling, storage, and payment.

Claude should be able to act as the creative producer and project manager, while HONE acts as the decentralized execution and settlement layer.

## Why MCP Matters

Without MCP, users must learn HONE-specific screens, endpoints, job structures, and workflow rules.

With MCP, the user can say:

- "Make me a TikTok ad for this product."
- "Turn this whitepaper into a 3-minute commercial."
- "Create a 30-minute pilot episode from this story bible."
- "Estimate the cost for a cinematic trailer."
- "Show me worker bids and choose the fastest trusted one."

Claude can translate intent into HONE job graphs.

## Role Split

Claude:

- understands user intent
- asks clarifying questions when needed
- drafts creative briefs
- writes scripts
- creates shot lists
- breaks long projects into milestones
- reviews outputs against the brief
- requests revisions
- summarizes cost, progress, and risks

HONE:

- exposes capabilities and pricing
- posts jobs on-chain or to the marketplace
- matches workers
- stores artifacts
- tracks escrow
- verifies delivery
- manages revisions/disputes
- returns final CIDs/files/status

## MCP Tool Surface

Initial tools:

### `hone_capabilities_list`

Returns available HONE capability classes:

- text inference
- image generation
- video generation
- voice synthesis
- music generation
- editing/assembly
- upscaling
- subtitles
- storage
- sensors

### `hone_video_presets_list`

Returns productized video presets:

- simple commercial
- long-form commercial
- TikTok / short vertical
- YouTube
- 30-minute TV-style show
- cinematic movie
- trailer
- music video
- product demo

### `hone_video_plan_create`

Input:

- preset
- topic/product/story
- audience
- duration target
- aspect ratio
- tone/style
- references
- budget
- deadline
- safety constraints

Output:

- treatment
- script outline
- scene list
- asset requirements
- worker capability requirements
- estimated cost
- milestone plan

### `hone_video_job_quote`

Returns price/range and likely completion time for a plan.

Should include:

- minimum viable cost
- recommended cost
- premium/fast cost
- expected worker requirements
- storage estimate

### `hone_video_job_post`

Posts a job or milestone set to HONE.

Input:

- accepted plan
- max budget
- escrow source
- revision policy
- artifact retention policy

Output:

- job id
- milestone ids
- escrow status
- expected next event

### `hone_video_job_status`

Returns:

- job state
- claimed workers
- current milestone
- partial artifacts
- ETA
- spend so far
- pending decisions

### `hone_video_artifact_get`

Returns artifact metadata:

- preview URL/CID
- final CID
- script
- shot list
- audio tracks
- captions
- project file bundle
- provenance metadata

### `hone_video_revision_request`

Lets Claude request a revision against the original plan:

- scene id
- issue
- requested change
- budget impact
- deadline impact

### `hone_job_accept`

Accepts completed work and releases escrow.

### `hone_job_dispute`

Opens a dispute when output does not match the accepted plan.

## Authentication

The MCP server should never rely on raw account names as authorization.

Supported auth options:

- local wallet session
- HONE API key generated by wallet
- signed challenge from owner/active key
- delegated project token with scoped permissions

Recommended for Claude:

- The user creates a scoped HONE project token.
- Token permissions:
  - read capabilities
  - create plans
  - request quotes
  - post jobs up to a spending cap
  - view artifacts
  - request revisions
  - accept jobs only if explicitly allowed

Dangerous actions should require confirmation:

- spending HONE
- accepting final output
- releasing escrow
- opening dispute
- publishing public artifacts

## Spending Controls

MCP must support hard limits:

- max spend per job
- max spend per day
- max spend per project
- max revision spend
- allowed preset types
- allowed content policy class

Claude should surface these limits before posting a job.

## Video Workflow Example

User:

> Make a TikTok ad for my local roofing company. Keep it under $20.

Claude:

1. Calls `hone_video_presets_list`.
2. Chooses `tiktok_short`.
3. Calls `hone_video_plan_create`.
4. Shows a short creative plan to user.
5. Calls `hone_video_job_quote`.
6. If under budget, asks for confirmation.
7. Calls `hone_video_job_post`.
8. Polls `hone_video_job_status`.
9. Reviews preview via `hone_video_artifact_get`.
10. Requests revisions or asks user to accept.
11. Calls `hone_job_accept` when approved.

## Implementation Shape

Start with a separate MCP server binary or Node package:

- `hone-mcp`
- talks to local `hone-node`
- can also talk to remote HONE gateway
- reads auth from local wallet or scoped token

Suggested local command:

```bash
npm run mcp:hone
```

Suggested Claude config:

```json
{
  "mcpServers": {
    "hone": {
      "command": "hone",
      "args": ["mcp", "serve"]
    }
  }
}
```

Current first implementation slice:

- `src/mcp/honeMcpServer.js`
- `npm run mcp:hone`
- Safe dry-run job posting only
- Exposes planning, quoting, status, artifact metadata, and Claude handoff tools over MCP stdio

For a local repo checkout before a `hone mcp serve` CLI exists, Claude can be configured with:

```json
{
  "mcpServers": {
    "hone": {
      "command": "npm",
      "args": ["run", "mcp:hone"],
      "cwd": "X:\\hone"
    }
  }
}
```

## MVP Tool Set

For the first version, implement only:

- `hone_capabilities_list`
- `hone_video_presets_list`
- `hone_video_plan_create`
- `hone_video_job_quote`
- `hone_video_job_post`
- `hone_video_job_status`
- `hone_video_artifact_get`

Add revision, acceptance, and disputes after the basic job lifecycle works.

## Strategic Value

HONE as MCP turns Claude into the natural frontend for the network.

This makes HONE easier to use and easier to explain:

> Claude plans the work. HONE does the work.
