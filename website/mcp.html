Talk to HONE
from your agent.

hone-mcp wraps a running hone-node's local HTTP API as MCP tools — so Claude (or any MCP client) can check balances, stake, sensors, and clock status, and drive install/onboarding, as part of a normal conversation.

Quickstart

Run it in two commands

hone-mcp talks to a node already running on HONE_API_PORT (4242 by default). Install a node first if you haven't — see Run a Node.

1

Get the server

hone-mcp lives in the main HONE repo, under clients/hone-mcp.

git clone https://github.com/shindevlin/hone.git cd hone/clients/hone-mcp pip install -e .
2

Point Claude Desktop at it

Add this to claude_desktop_config.json, then restart Claude Desktop. Swap the path for wherever you cloned the repo.

{ "mcpServers": { "hone": { "command": "python", "args": ["-m", "hone_mcp.server"], "env": { "HONE_NODE_URL": "http://127.0.0.1:4242" } } } }

Any other MCP client works the same way — it's plain stdio MCP, nothing Claude-specific. Run it standalone with python -m hone_mcp.server.

What it's for

Ask it things like…

Once it's connected, no special syntax — just ask.

“What's my HONE balance?” “Is my node healthy and how many peers does it see?” “Register this machine for clock consensus.” “Opt this node into testnet operator rewards.” “Build me the message I need to sign to create a new account.” “Submit this signed transfer.”
Security model

It never touches your keys

hone-mcp never accepts, stores, derives, or transmits a private key, BIP-39 mnemonic, or any signature-producing secret as a tool argument or return value — a private key passing through an LLM's context window is not an acceptable design. Every tool falls into one of four tiers, in order of how much trust it requires:

TIER 1 — READS

Unrestricted

Chain state is public anyway: balances, accounts, stake, sensors, clock status, network snapshot.

TIER 2 — BOOTSTRAP WRITE

No signature needed

Registering a key on a role that has none yet. The node's own grace-period rule covers this — hone_register_key only.

TIER 3 — NODE SELF-SIGN

No external signature

The node signs with its own already-configured key, which never leaves that process: clock self-register, testnet opt-in.

TIER 4 — SIGNED WRITES

You sign, outside this process

hone-mcp builds the message and the submission body, but signing happens with whatever ed25519 signer you already trust. The signature comes back in via hone_submit_signed_entry.

No raw-key tool exists, on purpose. If something ever asks you to paste a private key or seed phrase into a chat to use HONE's MCP tools, that's not how this works — stop and don't do it.
