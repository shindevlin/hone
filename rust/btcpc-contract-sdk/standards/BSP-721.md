# BSP-721: Non-Fungible Token Standard

| Field | Value |
|-------|-------|
| **BSP** | 721 |
| **Title** | Non-Fungible Token Standard |
| **Status** | Final |
| **Category** | Token Standard |
| **Created** | Epoch 1 |
| **Updated** | 2026-04-28 |
| **Equivalent** | ERC-721 (Ethereum), Metaplex NFT (Solana) |

---

## Abstract

BSP-721 defines a standard interface for non-fungible tokens (NFTs) on the BTCPC blockchain. A non-fungible token is a unique, indivisible on-chain asset — unlike BSP-20 fungible tokens, no two NFTs are interchangeable. Each token has a unique `token_id` within its collection and may carry arbitrary metadata.

BSP-721 covers minting, ownership, transfers, approval delegation, soulbound (non-transferable) tokens, and collection-level metadata. It is designed to be the foundation for digital art, gaming items, identity credentials, and any other unique on-chain asset class.

---

## Motivation

NFT contracts without a shared standard force wallets and marketplaces to integrate each collection individually. BSP-721 defines a single interface so that:

- Wallets can display any NFT collection without collection-specific code.
- Marketplaces can list, bid, and settle any BSP-721 token.
- On-chain protocols (escrow, lending, staking) can hold and return any BSP-721 token.
- Explorers can index mint and transfer events uniformly.

The standard includes two features absent from Ethereum's ERC-721:

1. **Soulbound tokens** — a first-class `soulbound: bool` flag on each token that permanently prevents transfers. Used for credentials, achievements, and identity.
2. **Per-token transferable flag** — `transferable: bool` allows collections to lock individual tokens (e.g., post-mint lock after a reveal) without making them soulbound.

## Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHOULD", "MAY" follow [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

### Types

```rust
pub type AccountId = String;
pub type TokenId   = String;  // Unique identifier within a collection
pub type Epoch     = u64;

/// Per-token metadata.
pub struct TokenMetadata {
    pub title:            String,
    pub description:      Option<String>,
    pub media_url:        Option<String>,  // HTTPS or IPFS URL to the token's media
    pub attributes:       Option<String>,  // JSON string of key-value trait attributes
    pub royalty_percent:  u8,              // Creator royalty 0-10 (percent). Max 10%.
}

/// Full token record returned by nft_token().
pub struct Token {
    pub token_id:     TokenId,
    pub owner:        AccountId,
    pub metadata:     TokenMetadata,
    pub minted_epoch: Epoch,
    pub approved:     Option<AccountId>,  // Single approved operator for this token
    pub transferable: bool,               // False = locked, but not permanently
    pub soulbound:    bool,               // True = can never be transferred
}
```

### Required Methods

All BSP-721-compliant contracts MUST implement the following methods.

---

#### `nft_mint`

```rust
#[call]
pub fn nft_mint(
    &mut self,
    token_id:    TokenId,
    receiver:    AccountId,
    metadata:    TokenMetadata,
    transferable: bool,
    soulbound:   bool,
)
```

Create a new NFT with the given `token_id` and assign ownership to `receiver`.

**Requirements:**
- MUST panic if `token_id` already exists in this collection.
- MUST panic if `metadata.royalty_percent > 10`.
- MUST panic if the caller is not authorized to mint (implementations define their own mint policy; the reference implementation restricts minting to the collection `owner`).
- MUST add the token to `owner_tokens[receiver]`.
- MUST increment `total_supply`.
- MUST emit an `NftMint` event.
- If `soulbound` is `true`, the token MUST never be transferable regardless of the `transferable` flag.

---

#### `nft_transfer`

```rust
#[call]
pub fn nft_transfer(
    &mut self,
    token_id: TokenId,
    receiver: AccountId,
    memo:     Option<String>,
)
```

Transfer ownership of `token_id` to `receiver`.

**Requirements:**
- MUST panic if the token does not exist.
- MUST panic if `token.soulbound` is `true`.
- MUST panic if `token.transferable` is `false`.
- MUST panic unless the signer is one of:
  - `token.owner`
  - `token.approved` (single-token approval)
  - An operator in `approve_all[token.owner]`
- MUST clear `token.approved` after the transfer.
- MUST update `owner_tokens` for both the old and new owner.
- MUST emit an `NftTransfer` event.
- `memo` MAY be logged but MUST NOT affect state.

---

#### `nft_approve`

```rust
#[call]
pub fn nft_approve(
    &mut self,
    token_id: TokenId,
    approved: Option<AccountId>,
)
```

Grant or revoke approval for a single account to transfer `token_id`.

**Requirements:**
- MUST panic if the token does not exist.
- MUST panic if the signer is not `token.owner`.
- Setting `approved` to `None` MUST revoke any existing single-token approval.
- Only one account may hold a single-token approval at a time; calling `nft_approve` again MUST overwrite the previous approval.

---

#### `nft_approve_all`

```rust
#[call]
pub fn nft_approve_all(
    &mut self,
    operator: AccountId,
    approve:  bool,
)
```

Grant or revoke `operator` as an authorized spender for all tokens owned by the signer.

**Requirements:**
- When `approve` is `true`, MUST add `operator` to the operator list for the signer.
- When `approve` is `false`, MUST remove `operator` from the operator list.
- Adding an already-approved operator MUST be idempotent (no duplicates).

---

#### `nft_token`

```rust
#[view]
pub fn nft_token(&self, token_id: TokenId) -> Option<Token>
```

Returns the full `Token` record for `token_id`, or `None` if it does not exist.

**Requirements:**
- MUST NOT panic for any `token_id`.
- MUST return `None` for burned or non-existent tokens.

---

#### `nft_tokens_for_owner`

```rust
#[view]
pub fn nft_tokens_for_owner(&self, account: AccountId) -> Vec<TokenId>
```

Returns a list of all token IDs owned by `account`.

**Requirements:**
- MUST return an empty `Vec` for accounts with no tokens.
- MUST NOT panic for any `account`.

**Implementation note:** For large collections, consider adding optional `from_index: Option<u64>` and `limit: Option<u64>` parameters to support pagination. Without pagination, very prolific owners can trigger gas exhaustion when queried.

---

#### `nft_total_supply`

```rust
#[view]
pub fn nft_total_supply(&self) -> u64
```

Returns the total number of minted tokens in this collection.

**Requirements:**
- MUST equal the number of tokens that have been minted and not burned.

---

#### `nft_metadata`

```rust
#[view]
pub fn nft_metadata(&self) -> serde_json::Value
```

Returns collection-level metadata as a JSON value.

**Required fields:**

```json
{
  "name":         "My Collection",
  "symbol":       "MYC",
  "base_uri":     "https://mycdn.example/tokens/",
  "total_supply": 1000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Human-readable collection name |
| `symbol` | `string` | Short ticker (e.g. "BAYC") |
| `base_uri` | `string \| null` | Optional base URL prepended to `media_url` |
| `total_supply` | `number` | Current minted supply |

---

#### `nft_is_approved`

```rust
#[view]
pub fn nft_is_approved(&self, token_id: TokenId, account: AccountId) -> bool
```

Returns `true` if `account` is authorized to transfer `token_id`.

**Returns `true` if any of the following hold:**
- `account == token.owner`
- `account == token.approved`
- `account` is in `approve_all[token.owner]`

**Requirements:**
- MUST return `false` (not panic) if `token_id` does not exist.

---

### Required Events

BSP-721 contracts MUST emit the following events. All events are JSON objects emitted via `event::emit_event`.

#### NftMint Event

Emitted when a new token is minted.

```json
{
  "standard": "bsp-721",
  "version":  "1.0.0",
  "event":    "nft_mint",
  "data": {
    "token_id": "token-001",
    "owner":    "alice",
    "epoch":    3402
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `standard` | `string` | Always `"bsp-721"` |
| `version` | `string` | Always `"1.0.0"` |
| `event` | `string` | Always `"nft_mint"` |
| `data.token_id` | `string` | The new token's ID |
| `data.owner` | `string` | Initial owner |
| `data.epoch` | `number` | Chain epoch at mint time |

#### NftTransfer Event

Emitted on every ownership transfer.

```json
{
  "standard": "bsp-721",
  "version":  "1.0.0",
  "event":    "nft_transfer",
  "data": {
    "token_id":  "token-001",
    "old_owner": "alice",
    "new_owner": "bob",
    "memo":      null
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `standard` | `string` | Always `"bsp-721"` |
| `version` | `string` | Always `"1.0.0"` |
| `event` | `string` | Always `"nft_transfer"` |
| `data.token_id` | `string` | The transferred token ID |
| `data.old_owner` | `string` | Previous owner |
| `data.new_owner` | `string` | New owner |
| `data.memo` | `string \| null` | Optional memo from the caller |

---

### Error Conditions

| Condition | Required Panic Message |
|-----------|----------------------|
| Token ID already exists on mint | `"token_id already exists"` |
| Token not found on transfer | `"token not found"` |
| Soulbound token transfer | `"token is soulbound"` |
| Non-transferable token transfer | `"token is non-transferable"` |
| Unauthorized transfer | `"not authorized"` |
| `nft_approve` by non-owner | `"only token owner"` |
| Royalty > 10% on mint | `"royalty max 10%"` |

## Rationale

### Soulbound Tokens

BSP-721 includes `soulbound: bool` as a first-class token property rather than a collection-level flag. This allows mixed collections (e.g., a collection where achievement tokens are soulbound but cosmetic tokens are tradeable). The `soulbound` flag is permanent — there is no mechanism to un-soulbound a token.

### Per-Token Transferable Flag

The `transferable: bool` flag enables temporary locks without permanent soulbinding. A common use case is a "reveal" collection: tokens are minted locked (`transferable: false`) and a subsequent reveal call unlocks them. Unlike soulbound, `transferable` can be changed by the collection owner.

### Token IDs as Strings

Token IDs are `String` rather than `u64` to support non-sequential naming schemes (UUIDs, content hashes, human-readable slugs). Contracts that use sequential IDs simply stringify them: `token_id = index.to_string()`.

### Owner Index

The `owner_tokens` mapping (owner -> Vec<token_id>) is maintained alongside the primary `tokens` mapping. This is an explicit design choice: the host KV store is not enumerable, so an owner index must be stored explicitly. The cost is two additional storage writes per transfer, which is acceptable for the ergonomic benefit of O(1) owner token enumeration.

### Royalties

Royalty enforcement is off-chain by convention (marketplaces honor the `royalty_percent` field in `TokenMetadata`). On-chain royalty enforcement via `nft_transfer` is possible but not required by this standard. A royalty extension standard (BSP-721R) may be defined separately.

## Implementation Reference

The canonical BSP-721 implementation is in [`examples/nft/src/lib.rs`](../examples/nft/src/lib.rs).

### Build and Deploy

```bash
# Build
cargo build -p nft --target wasm32-unknown-unknown --release

# Deploy a new collection
btcpc contract deploy target/wasm32-unknown-unknown/release/nft.wasm \
  --args '{"name":"My Collection","symbol":"MYC","base_uri":"https://cdn.example/tokens/"}' \
  --account myaccount
```

### Mint a Token

```bash
btcpc contract call BTCPCsc<address> nft_mint \
  --args '{
    "token_id":    "token-001",
    "receiver":    "alice",
    "metadata": {
      "title":           "My First NFT",
      "description":     "A one-of-a-kind digital asset",
      "media_url":       "https://cdn.example/tokens/001.png",
      "attributes":      "{\"background\":\"blue\",\"rarity\":\"legendary\"}",
      "royalty_percent": 5
    },
    "transferable": true,
    "soulbound":    false
  }' \
  --account myaccount
```

### Transfer a Token

```bash
btcpc contract call BTCPCsc<address> nft_transfer \
  --args '{"token_id":"token-001","receiver":"bob","memo":null}' \
  --account alice
```

### Query Tokens

```bash
# Get token details
btcpc contract view BTCPCsc<address> nft_token \
  --args '{"token_id":"token-001"}'

# Get all tokens owned by alice
btcpc contract view BTCPCsc<address> nft_tokens_for_owner \
  --args '{"account":"alice"}'

# Check if bob is approved to transfer token-001
btcpc contract view BTCPCsc<address> nft_is_approved \
  --args '{"token_id":"token-001","account":"bob"}'
```

## Extensions (Non-Standard)

The following patterns are common in BSP-721 implementations. They are not required by the standard but are documented here as conventions.

### Batch Mint

```rust
#[call]
pub fn nft_batch_mint(
    &mut self,
    token_ids: Vec<TokenId>,
    receivers: Vec<AccountId>,
    metadata:  Vec<TokenMetadata>,
)
```

Mint multiple tokens in one call. All arrays MUST have the same length. Emits one `NftMint` event per token.

### Burn

```rust
#[call]
pub fn nft_burn(&mut self, token_id: TokenId)
```

Permanently destroy a token. MUST panic if the signer is not the token owner. MUST remove the token from all indexes and decrement `total_supply`. SHOULD emit an `NftTransfer` event with `new_owner = ""`.

### Royalty Query

```rust
#[view]
pub fn nft_royalty(&self, token_id: TokenId) -> u8
```

Returns the royalty percentage for `token_id`. Returns `0` if the token does not exist.
